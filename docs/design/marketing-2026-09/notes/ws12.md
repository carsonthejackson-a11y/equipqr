## Decisions

- **No `.eq-rule` dividers.** `Security.dc.html` has no rules between the hero,
  the practices grid and the CTA (unlike the other screens), so none are
  rendered here; fidelity to the design file wins. Flip `rule` on the two later
  `Section`s if the orchestrator prefers the site-wide rhythm.
- **Inline links** (See also, the email in the CTA copy) use `text-eq-accent-300
  underline underline-offset-[3px]` with a hover to `text-eq-text`. The design
  uses the raw accent for these; the common rules say accent-coloured copy is
  accent-300, so that is the resting colour.
- The CTA is composed locally (`MailCtaPanel`, same class strings as
  `cta-panel.tsx`) because the primary must be an `<a>`, not a `Link` — see
  Requests. Swap it for `CtaPanel` once the request lands.
- `Reveal` wraps the hero header, the practices grid (one wrapper, as in the
  design's `data-reveal`) and the CTA box only; never the individual rows.

## Requests

- `_components/cta-panel.tsx`: let `primary`/`secondary` render a plain anchor
  for non-route hrefs (`mailto:`), e.g. `CtaAction = { href, label, external?:
  boolean }` → `render={external ? <a href={href} /> : <Link href={href} />}`
  with `nativeButton={false}`. `security/page.tsx` then becomes
  `<CtaPanel icon={Mail} titleId="disclosure-title" title="Found a security
  issue?" primary={{ href: mailHref, label: "Report an issue", external: true }}>…</CtaPanel>`
  and the local `MailCtaPanel` is deleted.
